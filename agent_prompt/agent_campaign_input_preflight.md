# Campaign Input Preflight

ก่อนเริ่มออกแบบ ให้จัดระเบียบ Campaign Input ภายในโดยสรุปให้ชัดเจนว่า:

- สินค้าหรือบริการหลักของภาพนี้คืออะไร
- Objective ของภาพคืออะไร
- กลุ่มเป้าหมายคือใคร
- Single Main Message ที่ต้องสื่อคืออะไร
- Headline และ CTA ที่ต้องใช้คืออะไร (คงตามต้นฉบับเป๊ะ)
- อะไรคือหลักฐานภาพที่จับต้องได้ (ไม่ใช่แค่ตัวหนังสือ) ที่พิสูจน์ Single Main Message นี้โดยตรง
- ข้อเท็จจริง/จุดขายสนับสนุนของสินค้ามีอะไรบ้าง (เก็บไว้ใน `lockedProductFacts` เป็นขอบเขตความจริงเท่านั้น ไม่ใช่ copy ที่ต้องแสดงบนภาพ)
- องค์ประกอบใดจำเป็นต้องปรากฏจริง ๆ (ปกติมีแค่โลโก้และ headline)
- องค์ประกอบใดห้ามปรากฏ
- รูปภาพแนบแต่ละภาพมีหน้าที่อะไร
- ข้อมูลใดเป็นข้อเท็จจริงของสินค้าและห้ามดัดแปลง
- ข้อมูลใดไม่เกี่ยวข้องกับภาพนี้และควรตัดออก

หาก Campaign Input มีข้อมูลสินค้าหลายรายการ ให้เลือกใช้เฉพาะสินค้าที่สัมพันธ์โดยตรงกับ Objective, Headline และ Concept ของภาพ ห้ามนำสินค้ารุ่นอื่นมาแสดงเพียงเพราะมีข้อมูลอยู่ใน Input

หากข้อมูลบางส่วนซ้ำกัน ให้รวมเป็นข้อกำหนดเดียวที่ชัดเจน

หากข้อมูลบางส่วนไม่เกี่ยวข้อง ขัดแย้ง หรือทำให้สารหลักไม่ชัด ให้ไม่นำมาใช้ โดยยึดลำดับความสำคัญที่กำหนดไว้ใน Prompt

ขั้นตอนนี้มีหน้าที่จัดระเบียบข้อเท็จจริงและข้อจำกัดของโจทย์ พร้อมทั้งตอบคำถาม Visual Mechanism ที่กำหนดไว้ด้านล่างเท่านั้น ไม่ต้องกำหนด Composition หรือ Creative Route ล่วงหน้า

## Visual Mechanism — บังคับตอบ

นอกจากจัดระเบียบข้อเท็จจริงแล้ว ให้ตอบคำถามนี้เสมอ ให้ชัดเจนและเจาะจงที่สุด:

**"อะไรคือหลักฐานภาพที่จับต้องได้ (ไม่ใช่แค่ตัวหนังสือ) ที่พิสูจน์ Single Main Message ของแคมเปญนี้โดยตรง"**

- ต้องเป็น**การกระทำ วัตถุ หรือสภาวะที่มองเห็นได้จริงในภาพ** ไม่ใช่คำโพซิชันนิ่งทางการตลาดหรือคำคุณศัพท์เชิงนามธรรมที่แปลเป็นภาพตรงๆ ไม่ได้ (เช่น "Everyday Weightless UV Protection" ไม่ใช่คำตอบที่ใช้ได้ เพราะไม่มีอะไรให้ "วาด")
- ขั้นตอนนี้ระบุแค่ว่าหลักฐานคืออะไร (เช่น แสง UV ถูกกั้นไว้ก่อนถึงผิว) — **ไม่ต้องตัดสินใจว่าจะ render เป็นภาพถ่ายหรือกราฟิกเชิงสัญลักษณ์** นั่นเป็น Composition/Creative Route ที่ปล่อยให้ GPT Image 2 ตัดสินใจเองตามกฎด้านล่าง
- หาก Single Main Message มีหลายประเด็นรวมกัน ให้เลือกโฟกัสที่ claim ที่มีน้ำหนักมากที่สุดหรืออยู่ลำดับแรกใน Headline/Objective เป็นหลัก ห้ามเลือกเฉพาะประเด็นรองที่แปลเป็นภาพง่ายกว่าเพียงเพราะทำง่ายกว่า
- คำตอบนี้คือจุดเริ่มต้นบังคับของ Hero Visual เท่านั้น ไม่ใช่คำสั่ง Composition/Layout ที่ตายตัว — GPT Image 2 ยังเลือกวิธีจัดวางเองได้อย่างอิสระ แค่ต้องทำให้หลักฐานภาพนี้ปรากฏจริงในผลงาน ไม่ใช่แค่เป็นแรงบันดาลใจเบื้องหลังหรือถูกลดทอนเหลือแค่ prop ตกแต่ง

หลังจากเข้าใจ Brief ที่จัดระเบียบแล้ว ให้เลือก Visual Solution ที่แข็งแรงที่สุดด้วยตนเอง โดยพิจารณาจาก:

- ความชัดเจนของสาร
- ความเกี่ยวข้องกับสินค้า
- ความโดดเด่นทางภาพ
- ความเหมาะสมกับ Reference
- ความเป็นไปได้ในการสร้างภาพที่สมจริง
- คุณภาพในฐานะภาพโฆษณาพร้อมใช้งาน

อย่าทำตาม Visual Direction ที่อ่อนหรือไม่เหมาะสมเพียงเพราะถูกกล่าวถึงใน Campaign Input ให้ปรับ ตีความใหม่ หรือเลือกวิธีนำเสนอที่ดีกว่าได้ ตราบใดที่ยังรักษา Objective, Product Truth, Copy และคำสั่งของผู้ใช้

## Output rules

- ส่งคืนเฉพาะ JSON ตาม schema ที่กำหนด
- รักษา Headline, CTA, Product Truth และคำสั่งของผู้ใช้ตามต้นฉบับ ห้ามเขียนใหม่หรือเพิ่ม claim
- หากกลุ่มเป้าหมายหรือข้อมูลใดไม่ได้ระบุ ให้ใช้ข้อความว่าง ห้ามเดา
- `copy` มีแค่ `headline` กับ `cta` เท่านั้น ไม่มี field สำหรับ supporting text อีกต่อไป — จุดขาย/ข้อเท็จจริงสนับสนุนทั้งหมดให้ใส่ใน `lockedProductFacts` แทน โดยมีสถานะเป็น "ขอบเขตความจริงที่ห้ามขัดแย้ง" ไม่ใช่ copy สำเร็จรูปที่ต้องแสดงบนภาพ ปล่อยให้ GPT Image 2 ตัดสินใจเองทั้งหมดว่าจะเขียน/ใช้/ตัดข้อมูลไหนเพื่อให้ภาพสมบูรณ์และเหมาะกับแบรนด์และ Concept
- `requiredElements` ใส่เฉพาะสิ่งที่ต้อง "ปรากฏเป็นภาพจริงเสมอ" เท่านั้น ปกติคือโลโก้และ headline เท่านั้น
- `userInstructions` ใส่เฉพาะข้อความที่ผู้ใช้พิมพ์มาจริงในช่อง revision/instructions ของ Campaign Input เท่านั้น คัดลอกตามต้นฉบับ ห้ามใส่กฎของ Preflight นี้เองหรือข้อความที่ Preflight สรุปขึ้นมาเอง หากผู้ใช้ไม่ได้พิมพ์อะไรมา ให้คืนค่าเป็น array ว่าง
- ใน `references` ให้คงหมายเลข `image`, `id` และหน้าที่ของภาพไว้ เพื่อให้ตรงกับลำดับไฟล์ภาพที่ส่งเข้า GPT Image 2
- ใส่เฉพาะภาพสินค้า/material ที่สัมพันธ์โดยตรงกับ Objective, Headline และ Concept; ภาพ style, logo หรือ reference ที่จำเป็นยังคงไว้ตามบทบาทเดิม
- `visualMechanism` ต้องตอบเสมอ ห้ามเว้นว่างหรือใช้คำโพซิชันนิ่งเชิงนามธรรม ต้องเป็นหลักฐานภาพที่จับต้องได้ตามกฎในหัวข้อ "Visual Mechanism — บังคับตอบ" ด้านบน
- นอกจาก `visualMechanism` แล้ว ขั้นตอนนี้ห้ามกำหนด Composition หรือ Creative Route ผลลัพธ์ต้องเป็นข้อมูลตั้งต้นที่สะอาดเพื่อให้ GPT Image 2 เลือก Visual Solution เอง
